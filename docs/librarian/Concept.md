# Concept — HoM 태그 도서관 (가칭)

> 상태: **초안 v0.2** (2026-09-07). v0.2: 범위를 공개 배포로 확정, 사서 증거 계층 재정렬. `[미확정]` 표시는 아직 결정 안 된 것.
> 이 문서는 "무엇을, 왜"만 다룬다. "어떻게"는 ToDo.md에서.

---

## 1. 한 줄 요약

Heart of Magic(HoM)에 **주문 태그 도서관**과 **태그 기반 학습 층**을 추가한다.
설치된 모든 마법 모드의 주문을 호환 패치 없이 자동으로 분류하고, 그 태그로
스킬트리 품질을 올리고, 태그를 게임 내 키워드로 노출해 다른 모드(퍽 모드 등)가 쓰게 한다.
**Spell Research는 쓰지 않는다.**

---

## 2. 왜 만드는가

### 2-1. 지금 상태의 문제

**HoM**은 트리 + XP 학습을 이미 갖고 있지만, 주문 간 관계(트리의 간선)를
이름·이펙트명의 TF-IDF로 판단한다(`edgeScoring.js:207`). 의미를 모르는 통계라
"소각"과 "화염구"가 가깝다는 걸 이름이 닮아서만 안다.

**Spell Research**는 아키타입(6축) 체계는 훌륭하지만
- 마법 모드마다 호환 패치를 손으로 만들어야 한다 — 매우 귀찮음
- 업데이트가 끊긴 지 오래
- 실측 결과 이 로드오더 커버리지 **3.35%** (정답셋 19개 플러그인 중 15개 미설치)
- 런타임 등록 경로가 검증되지 않았고 EditorID 조회도 불가(런타임 보존 안 됨)

**로드오더가 한글화**되어 있어 주문 이름의 85%가 한글이다.
이름 기반 접근은 시작부터 막혀 있다.

### 2-2. 해결 방향

패치 없이, 언어 무관하게, 자동으로 태그를 붙인다.
근거는 실측: 로드오더에 이미 KIT / OCF / NSV 키워드 체계가 깔려 있고,
전체 주문의 65.7%가 의미 키워드를 갖고 있다.
키워드만으로 만든 1차 분류기가 정밀도 79.8% / 재현율 49.3% —
이름 기반(69.3 / 27.0)의 재현율 1.8배, 그리고 **한글 이름에 영향받지 않는다.**

## 3. 도서관 모델

```
 [장서 수집]        [사서]              [목록]                  [손님]
 톰 기반 스캔  →  3단 분류기  →  spell_catalog.json  →  ┬ HoM 트리 (TF-IDF 특징량)
 (HoM 기존)       1회 실행         persistentId→tags     ├ 퍽 모드 (키워드 주입)
                                                          └ (보류) Spell Research
```

**장서 수집** — 어떤 주문이 도서관에 들어오나. 주문책이 있는 주문만.
HoM의 `ScanSpellTomes()`가 이미 이 정책이다. 전량 스캔(3552건)은 NPC·크리처·
이펙트용 주문이 섞여 있어 쓰지 않는다.

**사서** — 태그를 붙이는 분류기. 증거를 **범용성 순**으로 쌓는다. 위에서부터 시도:
1. **MGEF 구조** — 이펙트의 바닐라 키워드(`MagicDamageFire`, `MagicSummonUndead`…),
   archetype(Summon / Cloak / Paralysis / Reanimate / Bound Weapon…), primary AV, 저항 AV.
   모든 로드오더에 존재, 언어 무관, 프레임워크 불필요. **퍽 모드들이 조건으로 읽는 바로 그 키워드.**
   `[미측정]` — 현재 스캐너가 이 필드를 내보내지 않아 아직 잴 수 없음 (10절 1번)
2. 프레임워크 키워드 (KIT / OCF / NSV / ADAR) — **있으면 보너스.** 현재 로드오더 63.3% 커버.
   공개 배포에서는 있다고 가정할 수 없다: 이들을 빼면 주문의 97.7%가 키워드 0개
3. 이펙트명 · 설명문 (`[미확정]` 효과 미측정)
4. LLM 폴백 (`llmTreeFeatures.js` 재사용, 어휘를 우리 태그로 교체)

사서는 **한 번만 일한다.** 결과는 목록에 저장되고 손님이 올 때마다 재분류하지 않는다.

**목록** — `spell_catalog.json`. `persistentId → { 축 4개, elements[], techniques[], 출처(어느 단계가 붙였나), 신뢰도 }`.
단일 진실 원천. HoM이 이미 JSON을 읽고 쓰므로 형식이 자연스럽다.

**손님과 어댑터** — 손님마다 "우리 태그 → 그 손님의 언어" 규칙표 하나.
손님이 늘어도 사서는 바뀌지 않는다.

---

## 4. 태그 어휘

원칙: **가장 까다로운 손님보다 세밀하게.** 뭉치는 건 언제나 되지만 쪼개는 건 안 된다.

- 축 4개 — school(5) / tier(5) / casting(2) / targeting(4). 스캔 필드에서 기계적으로 도출
  (규칙은 HANDOFF 3절, 정답으로 검증됨)
- element — SR의 34종을 출발점으로, KIT/OCF에서 발견되는 개념 추가
  (예: wind→air 통합, blood·teleport 등 SR에 없는 것 보존)
- technique — SR의 15종을 출발점으로 동일하게 확장

어휘 확정은 ToDo 단계. SR 어휘를 그대로 쓰지 않는 이유: 그건 손님 한 명의 규칙일 뿐이고,
SR 라벨은 서사적(Oakflesh→nature)이라 기계적으로 100% 재현할 수 없다.

---

## 5. 학습 층 — HoM 확장

`[미확정]` 세부 규칙은 전부 열려 있음. 방향만:

- 주문 시전 시 그 주문의 태그별로 XP가 쌓인다
- 트리 노드 해금 조건에 "태그 XP 문턱"이 추가된다
- (옵션) 조건 달성 시 마법책을 인벤토리에 지급 — 원래 툴리우스 스펠트리 컨셉

이건 2026-08에 보류했던 "키워드 XP → 마법책 지급" 컨셉이 도서관 위에서 되살아나는 것.
당시 막힌 지점("키워드를 어디서 얻나")을 도서관이 해결한다.

## 6. 손님 목록

| 손님 | 어댑터 | 상태 |
|---|---|---|
| HoM 트리 | 태그 → `edgeScoring.js` 특징량 주입 | 자리 있음, 미구현 |
| 퍽 모드 | 태그 → 우리 키워드(`TSL_*`) 폼에 주입 + 손님별 고유 키워드 규칙 | `[미확정]` 어떤 퍽 모드가 무슨 키워드를 읽는지 미조사 |
| Spell Research | 태그 → 6축 → FormList | **보류.** 태그 완성 후 필요하면 규칙표만 추가 |

키워드 주입은 특정 손님용이 아니라 **범용 채널**이다.
키워드를 읽을 줄 아는 모든 모드가 잠재 손님이 된다.

## 7. 하지 않을 것

- Spell Research 게임플레이(연구 세션·저널·실험 실패) 재구현
- 절차적 주문 생성 — 마법책은 기존 BOOK 레코드 지급
- 이름 기반 분류를 1·2단계에 쓰는 것 (LLM 폴백에서만)
- SR 어휘를 우리 태그로 그대로 채택

## 8. 범위 — **공개 배포. 호환성 우선.** (확정)

이 결정이 강제하는 것:

- **프레임워크 의존 금지.** KIT / OCF / NSV / ADAR가 없는 환경이 기본값.
  실측: 이들을 제거하면 스캔 3552건 중 3472건(97.7%)이 키워드 0개.
  → 1차 증거는 반드시 MGEF 구조에서 나와야 한다. 프레임워크는 2차 보너스
- **스캐너 확장이 첫 번째 코드 작업.** 현재 스캐너는 SPEL 키워드만 읽는다.
  바닐라 `Magic*` 키워드는 SPEL이 아니라 MGEF에 붙어 있어 지금 덤프에 한 건도 없다.
  `effects[]`에 `keywords`, `archetype`, `primaryAV`, `resistance`를 추가해야 측정이 시작된다
- **퍽 모드 호환 = 바닐라 MGEF 키워드 보정.** 퍽 모드(바닐라·Adamant·Ordinator·Vokrii…)는
  `HasMagicEffectKeyword MagicDamageFire` 식으로 조건을 건다. 모드 주문의 MGEF에 이 키워드가
  빠져 있으면 화염 강화 퍽이 안 먹는다. 사서가 태그로 "이건 fire"를 알면 빠진 바닐라 키워드를
  MGEF에 **추가**해줄 수 있다. 새 키워드를 뿌리는 게 아니라 모두가 이미 읽는 키워드를 채우는 것 —
  이게 6절 "퍽 모드" 손님의 실체
- **비파괴 원칙.** 키워드는 추가만, 삭제 없음. 플러그인별 제외 목록 제공. 카탈로그는
  `persistentId` 키라 로드오더 변경에 안전
- **다국어.** 카탈로그와 사서 1·2단계는 이름을 보지 않으므로 언어 무관. UI 문자열은 HoM `lang/` 체계
