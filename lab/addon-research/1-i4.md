# I4 (Inventory Interface Information Injector, Nexus 85702) vs Heart of Magic

## 1. Format and matching
- Config: SKSE/Plugins/InventoryInjector/<PluginName>.json, loaded only if a plugin of that name is in the load order; later plugin wins (Nexus description, wiki Home). JSON: {"rules":[{"match":{...},"assign":{...}}]}.
- match keys seen in installed configs (count over all 29 jsons): formType 2383, keywords 1463, formId 1047 (single or anyOf), effectKeywords 457, spellType 235, school 201, subType, status, resistance, archetype, weightClass...
- Schema (github Exit-9B/InventoryInjector docs/InventoryInjector.schema.json): formType enum Enchantment|Spell|Scroll|Armor|Book|Ingredient|Light|MiscItem|Weapon|Ammo|Key|Potion|SoulGem. Spell/Scroll/Potion also: spellName, effectName, effectFlags, school, skillLevel, archetype, deliveryType, castTime, magnitude, duration, area. Book: teachesSpell (formId), teachesSkill, bookType, flags.
- Covers BOTH: tomes (formType Book, keywords on the book, or teachesSpell) and spells in the magic menu (formType Spell). Spell rules can read effectKeywords = keywords on the spell's MGEFs.
- Arrays: match-string-array supports plain list and {"anyOf":[..]} (seen: "effectKeywords": {"anyOf":["IconMagicSun","MAG_MagicDamageSun"]}).
- assign: iconSource (swf path), iconLabel, iconColor, subTypeDisplay.
- Not verified: AND/OR semantics of a plain list, exact match timing (wiki Matching page 404 via raw URL).

## 2. Per-pack add-ons (real examples)
Two layers, mostly KEYWORD based, but the keyword is attached by hand-written per-form lists:
- Abyss: `Abyss - Custom I4 Icons/I4AbyssIcons_KID.ini`:
  `Keyword = ADAR_BOOK_Shadow_Book|Book|ABY_SpellTomeAbyssalShadowDrain,ABY_SpellTomeShadowGraspAbyssal,...` (KID: hand-listed EditorIDs of every tome/scroll)
  `.../InventoryInjector/Abyss.json`: `{"match":{"formType":"Spell","effectKeywords":["ADAR_SPEL_Shadow_Cloak"]},"assign":{"iconSource":"I4AbyssIcons/I4AbyssIcons.swf","iconLabel":"Cloak","iconColor":"#4c4cff"}}` - the pack's MGEFs already carry ADAR_SPEL_* keywords (author put them in the ESP), the json maps keyword -> icon. Also Wheeler svg icons (KWD_ADAR_SPEL_Shadow_*.svg).
- Wish Magic: pure FormID: `WishMagic.json`: `"formType":"Spell","formId":{"anyOf":["WishMagic.esl|81C",...8 ids]}` -> `iconLabel":"magic_wishmagic"`; plus KID ini `Keyword = Rijosan_WishMagic|Spell|0x81C~WishMagic.esl,...`. Hand work per spell.
- So: one icon per pack/theme (few labels), assignment by hand-listed FormIDs/EditorIDs or by pack-internal MGEF keywords.
- Related, not icon rules: `[NoDelete] 0018 Known Spell Tomes Icon` = DIII dll + known_spells.json rule `"teachesKnownSpell": true` -> replaces icon with readIcon (dynamic, runtime). `0016 DynamicInventoryIconInjector.dll` is that framework. SpellHotBar2 - icon = unrelated csv/dds atlas per pack (different mod).

- BOOBIES books.swf (tome by school): book_spell_alteration #86c542, _conjuration #b361d3, _destruction #e12f2f, _illusion #2b9be3, _restoration #f5d730; book_herma_mora (Necrom). Keyed by BOOBIES keywords BoobiesBookTypeSpell<School> (set in BOOBIES_Skyrim_KID.ini, hand lists of vanilla tomes) and formId lists for mod packs (hand work).

Icon names inside the per-pack swf files not extracted (binary).

## 4. Feasibility
(a) Keywords route, no new DLL:
- MAG_MagicDamageSun / MAG_MagicDamagePoison are ALREADY attached by HoM adapters (adamant.json keywords list: MAG_MagicDamagePoison, MAG_MagicDamageSun, MagicDamageFire/Frost/Shock, MagicVampireDrain) and I4IconAddon.json already maps MAG_MagicDamageSun/Poison -> sun/poison icon. So with Adamant/Mysticism loaded, modded sun/poison spells already get icons today (if I4IconAddon.esp enabled). Fire/frost/shock: keyword is read by Skyrim.json? No, by resistance. Gap: IconMagicWind/Water/Earth/Blood: add an adapter file (tags air->IconMagicWind, water->IconMagicWater, earth->IconMagicEarth, blood->IconMagicBlood).
- BLOCKER found: I4IconAddon.esp is a 234-byte header-only stub (TES4 only, masters Skyrim/Update/Dawnguard/HearthFires/Dragonborn); I found no definition of keywords IconMagicWind/Water/Earth/Blood in the install (grep of *.ini and the esp). HoM adapter lines "rest" if the keyword is not in the load order (PERK_ADAPTERS.md). Not verified whether the keywords exist elsewhere (Nexus article 5041 says users add them via keywords; I couldn't fetch it). Use Mysticism MAG_ keywords as safe ones, or create keywords (new capability for HoM, not in current adapters).
- Tomes: adapters attach to MGEFs only. I4 Book rules have no "taught spell's effect keywords" key; only keywords on the book, teachesSpell formId, so tomes need KID-like keyword on the BOOK or generated rules per formId.
(b) Generating an I4 config from spell_catalog.json: one JSON file named after an active plugin (e.g. HeartOfMagic.json, needs a plugin of that name loaded; an ESP/ESL stub), rules like {"formType":"Spell","formId":{"anyOf":[...]},"assign":{...}} per tag->icon; and {"formType":"Book","teachesSpell":{...}} for tomes. Fully general, covers tomes and spells, any icon label incl. pack swf. Limit: file must exist before game start, i.e. generated by the panel scan in a previous session (catalog is written after scan); I4 likely reads config at data load (not verified), so a newly generated file takes effect next launch. Needs HoM to write into SKSE/Plugins/InventoryInjector/ (outside its own folder; MO2 VFS puts it in overwrite).
Simpler: (b) for coverage (tomes+spells, icon choice free) but one-session delay; (a) for zero-delay but limited to ~6 existing icons, keyword-existence blocker and no tomes. Neither handles pack-themed art (Abyss shadow icons): the pack's own swf/KID stays.
